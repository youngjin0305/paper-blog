# SparLeak: Privacy Leakage from Sparse Attention in LLM Inference on Shared GPUs

[원문](https://arxiv.org/abs/2609.38830v1) · [PDF](https://arxiv.org/pdf/2609.38830v1)

## 한눈에 보기

희소 어텐션(sparse attention)을 쓰는 LLM 추론이 입력에 따라 달라지는 KV cache 접근을 만들어 공유 GPU의 L2 cache·TLB에 흔적을 남긴다는 점을 짚고, 이 Sparsity-Induced Memory Access(SIMA) 부채널로 사용자 질의 속성과 생성 응답을 복원하는 SpaRLeaK를 제시한다. 3개 LLM·3종 희소 어텐션·3개 민감 데이터셋에서 속성 추론 90.9%, 응답 복원 87.3%의 평균 공격 성공률을 보고한다.

## 초록

희소 어텐션(sparse attention)은 현대 대규모 언어 모델(large language models, LLMs)에서 긴 컨텍스트 추론을 가속하기 위해 널리 사용되지만, 그 입력 의존적 실행 거동은 지금까지 탐구되지 않은 프라이버시 위험을 초래한다. 저자들은 희소 어텐션이 유발하는 비밀 의존적 key-value cache 접근 패턴에서 비롯되는 새로운 GPU 마이크로아키텍처 부채널을 식별하고 이를 Sparsity-Induced Memory Access(SIMA)라 부른다. 이 관찰에 기반하여, LLM 추론 중 SIMA 트레이스를 추출하고 두 가지 실용적 프라이버시 추출을 가능하게 하는 단계 인식(phase-aware) 부채널 공격 SpaRLeaK를 제시한다. 즉 prefill 단계 트레이스로부터의 질의 속성 추론(query attribute inference)과 decoding 단계 트레이스로부터의 자기회귀적 응답 재구성(autoregressive response reconstruction)이다. 페이지 수준 관측에서 근사적인 토큰 수준 희소성 프로파일을 재구성하고 프로파일링 기반 학습을 적용함으로써, SpaRLeaK는 사용자 질의 속성과 사적인 LLM 응답 내용을 포함한 민감 정보를 정확히 복원한다. 3개 LLM 아키텍처, 3개 희소 어텐션 메커니즘, 3개 프라이버시 민감 데이터셋에 걸친 광범위한 평가는 SpaRLeaK가 실제 LLM 서빙 환경에서 속성 추론에 90.9%, 응답 재구성에 87.3%의 평균 공격 성공률을 달성함을 보이며, 희소 어텐션 기반 LLM 시스템을 배포할 때 SIMA 누출을 고려해야 하는 중요성을 부각한다. 저자들은 익명화된 SIMA 트레이스, 학습된 공격 모델, 평가 스크립트, 문서를 아티팩트로 익명 저장소에 공개한다.

## 필요성

LLM의 광범위한 배포[41, 42]는 생성 품질을 높이고 환각을 줄이기 위해 점점 더 긴 컨텍스트를 쓰게 만들었으나, 어텐션의 이차 비용 때문에 긴 컨텍스트 추론은 계산 비용이 크다. 이 부담을 줄이기 위해 현대 LLM 시스템은 전체 어텐션을 토큰 부분집합으로 근사하는 희소 어텐션[5, 40, 60]을 점차 채택하고 있으며, 이 흐름은 SGLang[62], vLLM[18] 같은 긴 컨텍스트 서빙 시스템에 반영되어 있고 모델 규모와 컨텍스트 길이가 커질수록 강화될 전망이다.

문제는 효율을 위해 설계된 이 메커니즘이 새로운 프라이버시 위협을 만든다는 점이다. 희소 어텐션은 의미적 관련성에 따라 Key-Value(KV) 텐서를 동적으로 선택·인출하므로, GPU 메모리 계층에서 비밀 의존적(secret-dependent) 메모리 접근을 유발한다. 이 접근은 GPU 실행 내부에서 일어나고 LLM 서비스 인터페이스로 직접 노출되지는 않지만, cache와 TLB 같은 공유 GPU 마이크로아키텍처 구성요소에서 관측 가능한 경쟁(contention)을 만든다. 보안 관점에서 이는 기존 연구가 다루지 않은 SIMA 거동에 뿌리를 둔 새로운 부채널 표면이 된다.

타이밍[37, 50, 57, 63], 네트워크 트래픽[28, 48], 임베딩 cache 거동[1, 13]에 기반한 선행 부채널과 비교할 때, SIMA 부채널 표면은 모델 내재적(model-intrinsic)이며 prefill과 decoding 두 단계에 모두 걸쳐 있어 더 넓고 더 지속적인 프라이버시 누출을 가능하게 한다. 저자들은 이러한 성질이 희소 어텐션 메커니즘에 내재한 새로운 프라이버시 위험을 드러내며, 현대 LLM 배포 환경[38]에서 시기적절한 조사를 요구한다고 본다.

## 연구 분야 흐름

LLM 추론 효율화 연구는 전체 어텐션 점수를 명시적으로 계산하지 않고 중요한 토큰을 식별하는 방향으로 전개되어 왔으며, 논문은 이를 세 가지로 분류한다. (1) 모델 활성값이나 residual norm에서 중요도를 추론하는 activation-based saliency 계열[5, 40, 53, 60], (2) 블록이나 페이지 수준에서 어텐션을 근사하고 높은 점수를 받은 블록의 토큰을 유지하는 block-level scoring 계열[10], (3) 경량 모델로 중요한 토큰을 직접 예측하는 learned predictors 계열[12, 43, 52]이다. 이러한 토큰 선별은 activation-based saliency[5, 10, 53, 60], block-level scoring[40], 학습된 예측기[12, 43, 52] 등으로 구현되며, 관련 없는 토큰을 가지치기해 prefill 단계와 decoding 단계 비용을 모두 크게 줄인다.

한편 시스템 측면에서는 KV cache를 가상 메모리 페이지 단위로 관리하는 PagedAttention류 설계[18]와, prefill과 decoding을 분리해 처리량을 최적화하는 단계 분할 서빙[34, 64]이 자리 잡았다. 이처럼 희소 어텐션이 모델 수준에서 내리는 선택 결정이 페이지 단위 메모리 서브시스템을 통해 실현된다는 구조가, 이 논문이 겨냥하는 누출 경로의 전제가 된다.

## 관련 연구

**LLM의 프라이버시 누출.** 선행 연구는 LLM의 프라이버시 위험이 알고리즘 수준 또는 API 수준 노출에서 발생함을 보였다[8, 54]. 여기에는 학습 데이터 암기[2, 22, 46], 멤버십 추론(membership inference)[9, 15, 29, 49], 프롬프트 속성 추론[4, 16, 25, 39, 56]이 포함된다. 이러한 공격은 보통 모델 출력을 관찰하거나 조작된 프롬프트로 LLM과 상호작용하는 데 의존한다. 반면 SpaRLeaK는 추론 시 실행 거동을 표적으로 삼아, 희소 어텐션이 API 수준의 상호작용 없이도 공유 GPU 구성요소의 SIMA 부채널을 통해 민감 정보를 외부로 드러낼 수 있음을 보인다.

**LLM에 대한 부채널 공격.** 최근 연구들은 LLM 서빙 시스템이 타이밍 기반 공격[37, 50, 57, 63], 네트워크 트래픽 분석[28, 48], CPU cache 모니터링[1, 13] 등 다양한 부채널에 취약함을 밝혔다. Table 1은 대표적 공격들을 비교한다. Time Will Tell[57]은 응답 시간에서 응답 길이를, Early Bird[37]·PromptPeek[50]·InputSnatch[63]는 time-to-first-token 타이밍에서 KV Cache 적중/미적중(및 적중률, 서빙 순서)을 뽑아내 prefill 단계 공격을 수행하고, What Was Your Prompt[48]와 Whisper Leak[28]는 네트워크 트래픽(및 타이밍)에서 토큰 길이 시퀀스를 복원한다. Spill The Beans[1]와 I Know What You Said[13]는 임베딩 테이블에 대한 CPU 공유 cache에서 임베딩 접근 적중과 접근 순서를 관측한다. Table 1에서 이들 공격 대부분에는 적용 가능한 예방[6, 26, 30, 47, 61] 또는 탐지[6, 19] 기법이 제시되어 있는 반면, 이 논문이 다루는 sparsity-induced memory access 기반 누출에는 효과적인 완화책이 보고된 바 없다고 정리된다. SpaRLeaK는 희소 어텐션에 내재한 메모리 접근 거동을 악용한다는 점에서 근본적으로 다르며, 이 누출은 희소성에 의해 증폭되고 prefill과 decoding 두 단계에서 일관되게 나타나 질의 속성 추론과 자기회귀적 토큰 복원을 하나의 프레임워크로 묶는다. 또한 모델 실행에서 유도된 부채널 신호가 입력 내용을 정확히 복원하지 않고도 속성 수준 추론을 지원할 수 있다는 선행 결과[17, 23, 24]가 저자들의 질의 속성 추론 설계의 동기가 된다.

## 배경 지식

**어텐션 메커니즘.** 현대 LLM은 주로 Transformer 아키텍처[45]에 기반하며 핵심 구성요소는 multi-head self-attention이다. 추론은 두 단계로 구성된다. prefill 단계에서는 모델이 전체 입력 시퀀스를 병렬로 처리하고, 계산량과 메모리 비용은 입력 길이에 비례해 증가한다. decoding 단계에서는 새로 생성된 각 토큰이 이전에 처리된 모든 토큰에 어텐션한다. 중복 계산을 피하기 위해 현대 추론 엔진은 과거 토큰의 $K$, $V$ 표현을 저장해 decoding 스텝 사이에 재사용하는 KV cache를 유지한다[18, 20].

**GPU 메모리 접근 거동.** 토큰의 KV cache는 GPU의 high-bandwidth memory(HBM)에 저장되고 페이지 단위로 동작하는 GPU 가상 메모리 시스템이 관리한다[3, 31]. 최신 NVIDIA GPU에서 가상 메모리는 연속된 가상 주소 공간에 걸친 64 KB에서 2 MB 크기의 고정 페이지로 관리된다[3]. 반면 선행 연구에 따르면 단일 토큰에 연결된 KV 텐서는 레이어당 수 킬로바이트, 통상 10–30 KB 수준에 불과하다[18]. 따라서 하나의 GPU 메모리 페이지는 보통 여러 토큰의 KV 텐서를 함께 담는다. 희소 어텐션에서는 주어진 토큰에 대해 중요한 토큰 부분집합이 먼저 식별되고, 이 선택은 결국 메모리 서브시스템에서 페이지 단위로 실현된다. 토큰이 선택되면 그 KV 텐서를 담은 가상 메모리 페이지가 HBM에서 온칩 cache 계층으로 인출되고[7], 인출된 KV 텐서는 streaming multiprocessors(SMs)가 어텐션 계산에 소비하며, 선택되지 않은 토큰은 페이지 접근을 유발하지 않는다. 결과적으로 희소 어텐션은 각 페이지에 함께 배치된 여러 토큰의 활동을 암묵적으로 합산하는, 데이터 의존적 페이지 수준 메모리 접근 패턴을 만든다.

**단계별 희소성 패턴.** 저자들은 LLaMA3-8B[14]에 희소 어텐션을 켜고, 고정 system prompt와 사용자 질의를 이어 붙여 약 2K 토큰 길이의 프롬프트를 구성한 뒤(오픈소스 healthcare 데이터셋[35] 기반), prefill 단계에서 각 질의 토큰에 대해 근사 어텐션 점수[10]로 상위 10% 프롬프트 토큰을 선택하는 설정을 관찰한다. prefill 단계에서는 활성화가 크게 편향되어 소수 토큰이 일관되게 강조되고 대부분은 거의 주목받지 않으며, 희소성 패턴은 어텐션 레이어와 헤드에 따라 상당히 달라진다(Figure 2). decoding 단계에서는 각 스텝이 컨텍스트의 극히 일부만 활성화해 고도로 선택적이고 세밀한 패턴을 보이고, 활성 토큰은 레이어·헤드별로 뚜렷히 다르다(Figure 3). 또한 system prompt와 다른 속성을 고정하고 illness 범주만 바꾼 두 질의(예: *Obesity* 대 *Asthma*)는 같은 프롬프트 위에서 눈에 띄게 다른 누적 희소성 분포와 체계적이고 무시할 수 없는 차이를 보인다(Figure 4). decoding에서도 서로 다른 출력 토큰(예: *"his"* 대 *"health"*)이 명확히 다른 패턴을 유발하며, 의미적으로 가까운 *"health"* 와 *"healthy"* 조차 구별 가능한 패턴을 만든다(Figure 5). 희소 어텐션이 현재 토큰뿐 아니라 decoding 중 변화하는 이전 생성 컨텍스트에도 조건화되기 때문이다.

## 문제 정의

**위협 모델.** 희생자가 최신 GPU에서 희소 어텐션을 켠 추론을 수행하는 현실적인 LLM 서빙 배포를 가정한다. 구체적으로, 희생자 애플리케이션이 요청 전반에 공개되고 고정된 system-prompt 템플릿을 사용하되 사용자 질의와 생성 응답은 비공개인 서비스형 설정을 표적으로 하며, 이는 표준화된 템플릿을 노출·재사용하고 종종 prefix caching을 함께 쓰는 오픈소스 RAG·에이전트 애플리케이션에 해당한다. 공격자는 GPU 부채널 공격의 표준 공존(co-residency) 위협 모델[44, 63]에 따라 희생자와 같은 물리 GPU에서 비특권 스파이 프로세스를 실행한다. 공격자는 사용자 수준 CUDA 접근만 필요하며, 자신의 프로브 지연을 측정해 L2 cache 활동과 컨텍스트 전환에 걸친 TLB 잔류 같은 메모리 관련 마이크로아키텍처 효과를 관측한다[13, 44]. 특권 카운터, 드라이버 변경, 희생자 메모리 접근은 필요하지 않으며, KV 내용이나 정확한 희생자 주소를 직접 드러내지 않고 비밀 의존적 접근 패턴만 노출된다. 또한 공격자는 GPU 스케줄링이나 정확한 실행 타이밍을 제어할 수 없고, 고정 템플릿 서빙과 고정된 모델·런타임 구성 아래 해당 프롬프트 측 KV 페이지에 대한 경쟁 기반 프로브 매핑을 오프라인으로 보정해 여러 희생자 호출에 재사용할 수 있다고 가정한다. 공격 목표는 SIMA 부채널을 통해 사용자 질의와 LLM 응답에 관한 민감 정보를 추론하는 것으로, prefill 단계의 누적 SIMA 거동을 이용한 Query Attribute Inference(QAI)와 decoding 단계의 스텝별 SIMA 관측을 이용한 Autoregressive Token Recovery(ATR)로 구체화된다.

**기술적 난점.** SIMA가 유망하고 원리적인 공격 표면을 열어 주더라도 이를 실용적인 종단간 공격으로 바꾸는 일은 간단하지 않다. 첫째, SIMA 거동은 직접 관측되지 않는다. 공격자는 KV 접근이나 희소성 결정을 볼 수 없고 잡음이 있는 GPU 마이크로아키텍처 신호에서 간접적으로 추론해야 한다. 여기에 prefill과 decoding의 병렬성과 접근 패턴이 근본적으로 달라, prefill은 토큰을 병렬 처리하여 누적 신호를 노출하고 decoding은 토큰 단위로 진행되어 스텝별 신호를 노출한다[34, 64]. 두 단계는 시간 구조와 누출 특성이 다른 트레이스를 만들므로 단계별 추출 기법 설계가 필요하다. 둘째, 마이크로아키텍처 누출을 포착해도 공간적으로 거칠다. KV 텐서는 가상 메모리 페이지 단위로 관리되고[18] 관측되는 각 페이지 접근은 여러 토큰의 KV 상태를 집계하므로, 공격자는 다수의 토큰 수준 접근을 하나의 사건으로 뭉갠 페이지 수준 트레이스만 보게 되어 세밀한 희소성 구조가 흐려지고 개별 토큰이나 프롬프트 영역을 구별할 정보가 상당 부분 사라진다. 셋째, 희소 어텐션 트레이스는 명시적 어휘 내용이 아니라 계산적 중요도를 인코딩한다. 따라서 의미 있는 사적 정보를 복원하려면 잠재 접근 구조를 재구성하고 SIMA 트레이스와 고수준 의미 또는 토큰 정체성 사이의 통계적 관계를 학습해야 한다.

## 주요 기여

- **새로운 부채널 표면의 식별.** 희소 어텐션이 유발하는 비밀 의존적 KV cache 접근에서 비롯되는 GPU 마이크로아키텍처 부채널 SIMA를 식별하고, 희소 어텐션 기반 LLM 서빙의 마이크로아키텍처 프라이버시 누출을 처음으로 다룬 연구임을 제시한다. 이 누출은 모델 내재적이며 prefill과 decoding 두 단계에 걸쳐 나타난다.
- **단계 인식 공격 프레임워크 SpaRLeaK.** SIMA 거동을 악용하는 첫 단계 인식 부채널 프레임워크로서, GPU 마이크로아키텍처 신호를 관측해 각 단계의 입력 의존적 KV 접근 거동을 반영하는 SIMA 트레이스로 추상화하고, 이를 근사 희소성 패턴으로 변환해 희생자의 KV 내용에 접근하지 않고 민감 정보를 추론하는 구조적 신호로 사용한다. 전체 공격은 트레이스 추출, 희소성 패턴 재구성, 희소성 기반 추론의 3단계 파이프라인으로 구성된다(Figure 7).
- **두 가지 GPU 부채널 프리미티브.** GPU 실행 동역학만으로 두 단계를 구분한다. prefill은 전체 입력 컨텍스트에 대한 고도 병렬 계산을, decoding은 한 토큰씩의 순차 진행을 보인다는 전이를 이용해, prefill 단계에서는 L2 cache 기반 Invalidate+Compare 프리미티브로 누적 SIMA 트레이스를, decoding 단계에서는 TLB 기반 Evict+Reload 프리미티브로 스텝별 SIMA 트레이스를 추출한다.
- **페이지 수준 집계의 극복.** 정확한 복원을 시도하는 대신 희소 어텐션의 공간적 국소성과 분포적 규칙성을 활용하고 관측된 SIMA 트레이스와의 통계적 일관성을 강제함으로써, 후속 추론에 필요한 식별력을 되살릴 정도의 잠재 접근 구조, 즉 근사적 토큰 수준 희소성 프로파일을 재구성한다.
- **두 가지 종단간 추론 공격.** 재구성된 트레이스를 잠재 구조 신호로 보고 의미 속성 및 토큰 정체성과의 통계적 상관을 오프라인 프로파일링으로 학습해, prefill 트레이스에서 사용자 프롬프트의 고수준 의미 속성을 추론하는 QAI와 decoding 트레이스에서 생성 토큰을 복원하는 ATR을 실현한다. 두 경우 모두 공격자는 희생자의 모델, 프롬프트, 출력에 접근하지 않고 런타임에 학습된 매핑을 적용한다.
- **광범위한 평가와 완화책 검토.** 널리 쓰이는 여러 LLM, 희소 어텐션 메커니즘, 프라이버시 민감 데이터셋에 걸쳐 평가하여 질의 속성 추론 90.9%, 자기회귀적 토큰 복원 87.3%의 평균 공격 성공률을 얻고, 현실적 시스템 잡음과 모델 변화 아래에서도 원래 공격 효과의 90% 이상을 유지함을 보인다. 아울러 희소성 패턴에 입력 비의존적 무작위성을 주입하는 완화책을 평가하여, 공격 효과는 줄어들지만 추론 품질 저하라는 비용이 따른다는 점을 확인한다.
- **아티팩트 공개.** 익명화된 SIMA 트레이스, 학습된 공격 모델, 평가 스크립트, 문서를 익명 저장소에 아티팩트로 공개한다.

## 제시한 방법론

SpaRLeaK는 희소 어텐션(sparse attention)이 유발하는 희소성 유도 메모리 접근(Sparsity-Induced Memory Access, SIMA)을 이용하는 단계 인식(phase-aware) 부채널 공격 프레임워크다. 전체 파이프라인은 세 단계로 구성된다: ① 단계 인식 SIMA 트레이스 추출, ② 페이지 수준 트레이스로부터의 희소성 패턴 재구성(sparsity pattern reconstruction), ③ 희소성 기반 추론 공격. 최종 산물은 프리필(prefill) 단계 트레이스를 이용한 질의 속성 추론(Query Attribute Inference, QAI)과 디코딩(decoding) 단계 트레이스를 이용한 자기회귀 토큰 복원(Autoregressive Token Recovery, ATR)이다.

### 위협 모형과 설계 전제

피해자는 희소 어텐션이 켜진 LLM 추론을 현대 GPU에서 수행하며, 공격자는 동일 물리 GPU에 상주하는 비특권 스파이 프로세스를 실행한다(GPU 부채널의 표준 co-residency 가정 [44, 63]). 공격자는 사용자 수준 CUDA 접근만 필요하고, 자신의 프로브 지연 시간을 측정해 L2 캐시 활동과 문맥 전환에 걸친 TLB 잔존(residency)을 관찰한다. 특권 카운터, 드라이버 수정, 피해자 메모리 접근은 불필요하며 KV 내용이나 정확한 피해자 주소는 복원되지 않는다. 서비스 설정상 시스템 프롬프트 템플릿은 공개·고정이고 사용자 질의와 응답만 비공개이며, 모델과 런타임 설정이 고정되어 있으므로 프롬프트 측 KV 페이지에 대한 경쟁 기반 프로브 매핑을 오프라인으로 캘리브레이션해 여러 호출에 재사용할 수 있다는 점이 설계의 핵심 전제다. 장수명 모델 프로세스가 요청 간 KV 할당을 재사용하므로 이 매핑이 계속 유효하다는 논리다.

### ① 단계 구분과 SIMA 트레이스 추출

프리필과 디코딩은 GPU 실행 패턴으로 구분한다. 프리필은 전체 문맥에 대한 단일 순방향 패스로 짧고 집중된 연산 집약 커널 버스트를 만들어 커널 시간 밀도가 높고, 디코딩은 토큰마다 증분 패스를 수행해 준주기적(near-periodic) 구조의 긴 실행 트레이스를 만든다. 전이 지점 탐지는 Nsight Systems [32]의 커널 타임라인을 독립적 경계 기준으로 쓰며(해당 환경에서 root 없이 접근 가능), 커널 시간 기반 이용률 프록시

$$util(w) = \frac{\tau}{|w|}$$

로 GPU 활동을 정량화한다. 여기서 $\tau$는 고정 윈도 $w$ 내 누적 커널 실행 시간, $|w|$는 윈도 길이다. LLM 연산을 지배하는 GEMM 커널에 한정하면 더 깨끗하고 안정적인 신호가 얻어지며, 동일한 전이는 수집된 L2/TLB 트레이스의 강도와 주기성에서 직접 추정할 수도 있다.

**프리필: 누적 SIMA 트레이스.** 프리필 누출을 누적 SIMA 트레이스 $\{c_1, c_2, \dots, c_N\}$로 정의한다($N$은 감시 대상 프롬프트 측 KV 페이지 수, $c_i$는 질의 토큰 어텐션 계산 전반에서 페이지 $p_i$가 접근된 빈도 추정치). 반복적 희소 접근이 공유 L2 캐시에 측정 가능한 교체 압력을 만든다는 관찰을 활용한다. GPU L2 교체 정책은 문서화되어 있지 않지만 캐시 경쟁이 안정적인 축출 거동을 낸다는 선행 결과 [59]에 기대어, 오프라인 캘리브레이션에서 각 페이지 $p_i$에 대해 축출 거동이 $p_i$ 접근과 상관되는 캐시 라인 정렬 프로브 주소 집합 $s_i$를 구성한다. 런타임에는 `WRITE_CACHE(`$s_i$`)`로 프로브 라인을 L2에 채우고 기본 GPU 스케줄링 하에서 피해자가 프리필을 수행하는 동안 Invalidate+Compare 프리미티브 [59]와 함께 `READ_CACHE(`$s_i$`)`를 적용한다. $p_i$ 접근이 경쟁 라인을 유입시키므로 접근이 잦을수록 $s_i$에 더 큰 축출 흔적이 남고, 이를 프리필 구간에서 누적해 $c_i$를 추정한다. 정확한 접근 횟수는 드러나지 않지만 상대적 페이지 수준 희소성은 신뢰성 있게 포착되며, 이는 후속 재구성과 추론에 충분하다는 설계 판단이다.

**디코딩: 단계별 SIMA 트레이스.** 디코딩 희소성은 단계별(step-wise) SIMA 트레이스 $\{b_1^{t}, b_2^{t}, \dots, b_N^{t}\}$로 특성화하며, $b_i^{t} \in \{0,1\}$은 단계 $t$에서 페이지 $p_i$의 KV가 희소 어텐션에 의해 접근되었는지를 나타낸다. 누적 트레이스와 달리 단계별 페이지 참여를 이진으로 포착하고 디코딩 진행에 따라 변화한다. 구현은 가상-물리 페이지 번역을 캐싱하는 GPU TLB의 Evict+Reload 프리미티브 [58]를 사용한다. 선행 연구의 TLB 집합 캘리브레이션 방법론 [58]에 따라, 감시 페이지 $p_i$마다 공격자 주소 공간에 후보 페이지를 할당하고 $p_i$와 동일하거나 크게 겹치는 TLB 집합에서 번역이 충돌하는 프로브 페이지 $q_i$를 선택한다. 또한 오프라인 프로브 트레이스의 주기성으로 평균 디코딩 스텝 길이를 추정해 한 생성 스텝을 대략 덮도록 프로빙 윈도 길이 $\Delta$를 설정하며, 구현상 한 프로빙 라운드가 $\Delta$ 내에 끝나 스텝 단위 관측이 가능하다. 각 윈도에서 프로브 페이지 번역을 준비하고 피해자 실행 후 $q_i$를 재적재해 번역 지연을 측정한다. $p_i$ 접근으로 TLB 경쟁이 발생하면 $q_i$의 번역 엔트리가 밀려나 높은 재적재 지연이 나타나므로, 캘리브레이션된 임계값 초과 시 $b_i^{t}=1$, 그 외에는 $b_i^{t}=0$으로 둔다. 스케줄링 지터 등으로 $\Delta$가 단일 디코딩 스텝과 정확히 정렬되지 않을 수 있어, 인접 프로빙 윈도의 측정을 합치고 다수결 투표(majority voting)로 일시적 잡음을 억제한다.

### ② 희소성 패턴 재구성

페이지 단위 관측은 여러 토큰의 활성을 한 값으로 압축해 페이지 내 미세 정보를 잃는다. 페이지 내 접근을 토큰에 균일 분배하는 단순 재구성은 희소 어텐션의 강한 비균일 구조를 보존하지 못한다. 저자들은 대신 페이지 수준 누적 접근 빈도가 페이지 내 잠재 토큰 수준 활성 분포와 상관된다는 통계적 단서를 활용한다. 페이지 크기 10토큰 기준 분석에서 누적 빈도가 높은 페이지는 치우친 롱테일(long-tailed) 토큰 활성 분포를, 낮은 페이지는 평평하고 균일한 분포를 보였다(예: 27번째 페이지는 고빈도 영역으로 소수 토큰이 활성을 지배, 156번째 페이지는 저빈도 영역으로 균등 분포). 이는 희소 어텐션이 모든 질의 토큰에 대해 소수의 매우 관련 높은 프롬프트 토큰만 반복 재사용하고 대부분 토큰은 거의 선택하지 않기 때문 [51, 65]이며, 페이지 빈도가 토큰 활성의 합이므로 빈번히 선택되는 토큰을 포함한 페이지가 자연히 높은 총빈도와 집중된 토큰 수준 분포를 갖는다. 이에 따라 프리필에서는 분포적 재구성(distributional reconstruction)을 수행해, 각 페이지의 관측 빈도를 토큰 수준 희소성 분포의 집중도를 결정하는 제어 신호로 취급한다. 고빈도 페이지는 더 치우친 토큰 참여로, 저빈도 페이지는 더 평평한 참여로 모델링하고, 관측된 페이지 수준 빈도와의 일관성을 유지하도록 토큰 수준 희소성을 생성한다.

디코딩 단계는 과제가 다르다. 단계별 트레이스는 페이지당 이진 관측만 제공해 활성 페이지 내부의 활성 패턴을 드러내지 않으므로, 각 디코딩 스텝에서 활성 페이지의 공간적 분포를 추가 정보로 쓴다. 10개 연속 토큰 단위 페이지 분할 하에서(예시: 5번째 디코딩 스텝), 페이지 수준에서 밀집 활성되는 영역은 활성 토큰을 여럿 포함하고 희소 활성 영역은 소수의 활성 토큰만 갖는 경험적 상관이 관찰된다(156번째 페이지 주변은 빈번한 페이지 활성과 다수의 활성 토큰, 46번째 페이지 주변은 드문 활성과 제한된 토큰 활동). 정확한 활성 패턴은 스텝과 토큰마다 변하지만 페이지 내 활성 토큰 수는 페이지 수준 SIMA 트레이스의 국소 밀도를 긴밀히 따른다. 이는 디코딩 희소 어텐션의 국소성 때문인데, 선택된 토큰이 프롬프트 전역에 균일하게 퍼지지 않고 소수의 연속 영역에 군집하므로 군집 선택은 밀집 페이지 활성으로, 고립 선택은 희소 페이지 신호로 투영된다. 따라서 SpaRLeaK는 대상 페이지 주변 페이지 수준 활성의 국소 밀도를 페이지 내 토큰 참여 정도의 프록시로 삼아, 관측 트레이스와 일관되면서 희소 어텐션의 공간 구조와 단계별 동역학을 보존하는 대표적 토큰 수준 희소성 패턴을 생성한다.

### ③ 희소성 기반 추론 공격

**QAI.** 프리필 단계에서 재구성한 토큰 수준 희소성 프로파일을 입력으로 하는 지도 분류 문제로 정식화한다(선행 추론 공격 [27, 33]과 일관). 오프라인 프로파일링에서 공격자는 자신의 질의로부터 알려진 속성 레이블과 짝지어진 희소성 프로파일을 수집하고, 분류기는 구조적 패턴과 의미 속성의 연관을 학습해 피해자 질의 텍스트 없이 온라인 추론을 수행한다. 두 가지 설계 요소가 있다. 첫째, 스케일 불변성을 위한 정규화: 토큰 수준 프로파일은 질의 길이와 전체 어텐션 활동량에 영향받으므로 각 프로파일을 정규화해 전역 스케일 차이를 제거하고, 프롬프트 토큰 전반의 상대적 희소 어텐션 분포를 강조한다. 둘째, 교차 레이어·교차 헤드 특징 구성: 희소 어텐션 결정이 레이어와 헤드별로 독립적으로 이루어져 서로 보완적 정보를 담으므로, 신호를 조기에 합치지 않고 모든 레이어·헤드의 희소성 특징을 유지해 단일 표현으로 연결(concatenate)하여 교차 레이어 규칙성과 변동성을 보존한다.

**ATR.** 디코딩 중 재구성한 단계별 토큰 수준 희소성 프로파일로 응답을 토큰 단위 복원하며, 각 디코딩 스텝에서의 분류로 정식화한다. 오프라인 프로파일링에서 단계별 프로파일과 알려진 출력 토큰을 짝지어 감시 대상 레이어 및 KV 헤드의 특징을 연결해 토큰 분류기를 학습하고, 온라인에서는 피해자 출력 접근 없이 재구성 프로파일에 분류기를 순차 적용한다. 두 가지 보강이 들어간다. 순차 특징 증강(sequential feature augmentation)은 자기회귀 생성의 강한 시간 의존성을 특징 차원 증가 없이 포착하기 위해 각 스텝 표현에 선행 스텝들의 집계된 희소성 정보를 덧붙여, 희소성 패턴이 디코딩 진행과 함께 변하는 시간적 규칙성을 이용하게 한다. 제한된 토큰 예측 공간(restricted token prediction space)은 전체 어휘 분류의 복잡도와 클래스 불균형을 줄이기 위해 오프라인 프로파일링 코퍼스에서 과제별 후보 집합을 구성하는데, 이 집합은 온라인 실행 전에 고정되고 동일 과제 내에서 재사용되며, 성능 이득이 SIMA에서 오는지 후보 집합 제한에서 오는지는 보충 실험으로 검증한다. 추론 공격의 분류기는 재구성된 희소성 패턴 위에 학습되는 경량 MLP 기반 분류기로 구현된다.

### 프로파일링 설정과 하이퍼파라미터

주 설정은 모델 체크포인트, 토크나이저, 희소 어텐션 구현과 설정이 공개임을 가정하고, 설정 불일치와 SIMA 누출을 분리하기 위해 공격자가 계측된 복제본(instrumented replica)을 통제된 입력으로 실행해 정답 희소성 패턴을 수집하고 예측기를 학습한다. 이 프로파일링은 별도 GPU에서 수행할 수 있으나 페이지 프로브 캘리브레이션은 대상 특정적이다. 모델당 QAI 질의 5,000개, ATR 응답은 LongChat-7B/LLaMA3-8B/Qwen3-8B에 각각 3,000/3,000/2,000개를 사용하고, 8:1:1의 표본 비중복(sample-disjoint) 분할과 과제별 18층/34층 잔차 예측기를 쓴다. 비용은 LLM 추론이 지배하며 QAI는 질의당 프리필 1회, ATR은 디코딩 전 구간의 단계별 패턴을 기록해 응답 길이에 비례한다(예: QAI는 모델별 0.86h/0.82h/1.10h, ATR은 12.7h/15.2h/19.5h). 예측기 학습 오버헤드는 무시할 수준이고 동일 설정을 쓰는 공격들에 일회성 비용이 분할 상환된다. 모델 가중치나 희소 어텐션 설정을 얻을 수 없으면 대상 상호작용 프로파일링(target-interactive profiling)으로 전환해, 공격자가 선택 질의를 제출하는 동안 동일 GPU의 스파이가 실제 페이지 수준 SIMA 트레이스를 기록하고 공격자가 아는 속성과 반환 토큰을 QAI·ATR 레이블로 사용한다. 이 트레이스–레이블 쌍으로 직접 학습해도 평균 PASR 90.97%, DASR 86.65%를 달성하며 복제본 기반 대비 최대 감소폭은 각각 1.28, 1.54 퍼센트포인트에 그친다.

### 완화 기법 설계

제안된 직접적 완화는 입력 비의존(input-independent) 무작위성을 통제된 형태로 주입해 희소성 패턴이 노출하는 정보를 줄이는 것이다. 추론 중 중요도 점수로 선택된 토큰 중 $A\%$를 입력과 무관하게 다른 토큰으로 무작위 대체하여, 입력 의존적 희소성 패턴의 안정성을 교란하고 SIMA 트레이스의 식별력을 떨어뜨린다. 다만 대체 토큰이 의미적으로 덜 관련되어 선택 문맥이 약화되고 특히 높은 교란 강도에서 생성 품질이 저하된다. 이 외에 세밀한 타이머·모니터링 인터페이스·메모리 관리 프리미티브 제한(비밀 의존 접근 자체는 없애지 못하나 트레이스 충실도 저하), 고정 혹은 페이지 패딩된 스케줄과 더미 KV 접근(희소 어텐션 효율 희생), 테넌트 격리 및 캐시/TLB 파티셔닝(런타임 또는 하드웨어 지원 필요), 반복 프로빙·비정상 캐시/TLB 활동 탐지가 보완책으로 논의된다.

## 실험 및 평가

### 평가 설정

**모형(Models).** 서로 다른 계열의 대표적 LLM 세 종을 평가한다: LongChat-7B [21], LLaMA3-8B [14], Qwen3-8B [55]. 각 모형에는 세 부류의 희소 어텐션(sparse attention) 기법을 적용한다. (1) 중간 활성값을 비교해 중요 토큰을 식별하는 activation-based saliency [5, 53, 60], (2) 토큰을 블록·페이지 단위로 묶어 블록 수준에서 근사 어텐션 점수를 계산하는 block-level scoring [10, 40], (3) 경량 예측기로 핵심 토큰을 직접 고르는 learned predictors [12, 43, 52].

**데이터셋(Datasets).** 프라이버시 민감 평가를 위해 Healthcare [35], Financial QA [36], Legal QA [11] 세 가지를 사용한다. Healthcare는 각 샘플이 속성값만 담고 있어, 공개 모형이 생성한 템플릿으로 속성을 비정형 질의(query)로 변환해 추론 요청을 구성한다. Financial QA와 Legal QA는 질의 내 여러 속성을 요약해 속성 추론 공격이 가능하도록 만든다. 구성된 질의는 모두 배포된 LLM에 투입해 응답을 생성하고, 이 응답으로 Autoregressive Token Recovery(ATR) 공격을 수행한다.

**평가 지표(Metrics).** prefill과 decoding 단계를 분리해 단계별 공격 성공률로 측정한다. prefill 단계 공격 성공률(PASR)은 해당 속성을 포함한 질의 중 속성 예측이 맞은 비율이며, decoding 단계는 DASR로 보고한다. 완화 기법 평가에서는 PASR과 DASR의 평균을 전체 ASR로, 생성 품질은 ROUGE로 보고한다.

**실험 환경(Environment).** NVIDIA L20 GPU(48GB), Ubuntu 20.04(Linux 5.15.0), NVIDIA 드라이버 550.67, CUDA 11.8, PyTorch 2.6.0.

**신호 조건.** 결과는 네 가지 신호 조건으로 구분한다. 토큰 수준 오라클 패턴 O(T), 재구성된 오라클 페이지 패턴 O(P+R), 가공 없는 페이지 수준 관측 R(P), 그리고 재구성된 실관측 R(P+R)이다. R(P+R)이 완전한 end-to-end 공격에 해당한다. 표 2의 각 항목은 20회 실행에 대한 평균 ± 95% 신뢰구간이다.

### 주요 결과

**전반적 효과.** end-to-end 공격에서 평균 PASR은 모든 데이터셋에서 91%를 넘고, DASR은 84.6%에서 89.4% 범위로 모든 설정이 80%를 상회한다. 논문 전체 평균으로는 속성 추론 90.9%, 응답 복원 87.3%를 달성한다. O(T)의 높은 성능은 토큰 수준 희소성 패턴 자체가 비공개 질의와 생성 응답에 관한 상당량의 정보를 내재적으로 담고 있음을 확인해 준다. O(P+R)은 O(T)와 약 1퍼센트포인트 이내 차이에 머물러, 재구성 후에는 페이지 집계로 인한 정보 손실이 제한적임을 보인다. end-to-end 성능은 토큰 수준 오라클보다 약 2.5포인트 낮은 수준으로, 재구성이 잡음 섞인 페이지 수준 트레이스에서 정보 대부분을 회복함을 뜻한다.

**속성 복잡도의 영향.** PASR은 속성 유형에 따라 달라진다. Healthcare의 _Gender_ 처럼 클래스 수가 적은 속성은 약 97.9%로 거의 완전한 정확도에 이르고, Financial QA의 _Entity_ 처럼 레이블 공간이 큰 속성은 약 87.3%로 낮아진다. 표 2에서 LLaMA3-8B·learned predictors 조건의 R(P+R) 값을 보면 Gender는 99.4%, Illness(60개 클래스)는 98.7%, Blood는 99.8%이고, 같은 조건의 R(P)에서는 Illness 74.4%, Age 81.3%, Blood 85.6%로 재구성 이전의 성능이 크게 낮다. DASR은 출력 시퀀스를 복원하는 방식이라 속성 의미에 덜 민감하지만, Financial QA는 응답의 어휘적 다양성과 구조적 복잡성 때문에 Healthcare·Legal QA보다 일관되게 낮은 DASR을 보인다.

**희소 어텐션 기법의 영향.** 두 단계 모두에서 기법별 차이가 나타난다. activation-based 방법의 prefill PASR이 약 86.4%로 가장 낮고, block-level scoring이 중간, learned predictors가 약 95.5%로 가장 높다. decoding도 같은 경향으로 learned predictors가 데이터셋·백본 전반에서 최고 성능을 보인다. 희소성 추정이 정확할수록 SIMA 트레이스의 정보 손실이 줄어 속성 추론과 토큰 복원 모두에 유리하다는 해석이다.

**LLM 구조의 영향.** 평균 prefill PASR은 LongChat-7B 약 90.6%, LLaMA3-8B 약 89.4%, Qwen3-8B 약 92.7%다. Qwen3-8B는 데이터셋 전반에서 가장 높은 decoding DASR을 기록하는데, 층과 헤드에 걸친 희소성 패턴이 더 안정적·변별적이어서 더 깨끗한 SIMA 신호를 낸다는 설명이다.

### Ablation

제안한 재구성 기법의 효과를 검증하기 위해, 정답 토큰 수준 희소성 패턴을 5~20 토큰 단위 페이지로 집계해(실제 KV 페이지 granularity를 반영) 재구성 전후의 PASR과 DASR을 측정한다. 페이지 집계가 거칠어질수록 토큰 수준 정보가 가려져 재구성 없이는 두 공격 모두 성능이 저하된다. 페이지 크기 20에서 Healthcare PASR은 재구성 없이 57.45%까지 떨어지지만, 재구성을 켜면 훨씬 높은 수준을 유지한다. 추가 ablation은 제출된 보충 자료에 수록되어 있다고 밝힌다. 또한 ATR에서 전체 어휘 분류의 복잡도와 클래스 불균형을 줄이기 위해 오프라인 프로파일링 코퍼스로 과제별 후보 토큰 집합을 구성하는데, 성능 향상이 SIMA에서 오는지 아니면 이 제한된 후보 집합에서 오는지는 보충 실험에서 따로 검토한다.

### 실용성 분석

**프로파일링 비용.** 기본 평가는 모형 체크포인트, tokenizer, 희소 어텐션 구현과 설정이 공개라고 가정하고, 공격자가 계측된 복제본(replica)을 통제된 입력으로 돌려 정답 희소성 패턴을 모아 예측기를 학습한다. 모형당 QAI 질의는 5,000개, ATR 응답은 LongChat-7B/LLaMA3-8B/Qwen3-8B에 각각 3,000/3,000/2,000개를 쓰고, 8:1:1로 샘플 비중복 분할하며 과제별로 18층·34층 residual 예측기를 사용한다. 표 3에 따르면 비용은 LLM 추론이 지배한다. QAI는 질의당 prefill 시간이 각각 0.62s, 0.58s, 0.79s로 총 0.86h, 0.82h, 1.10h이며, ATR은 토큰당 디코딩 시간 0.05s, 0.06s, 0.07s에 평균 응답 길이 300, 300, 500을 곱해 12.7h, 15.2h, 19.5h가 든다. 예측기 학습 오버헤드는 무시할 수준이고, 이 일회성 비용은 동일 설정의 여러 공격에 분산된다. 모형 가중치나 희소 어텐션 설정을 알 수 없을 때는 target-interactive profiling으로 전환해, 공격자가 선택 질의를 보내는 동안 co-resident spy가 실제 페이지 수준 SIMA 트레이스를 기록하고 공격자가 아는 속성과 반환 토큰을 레이블로 쓴다. 이 trace–label 쌍만으로 학습해도 평균 PASR 90.97%, DASR 86.65%를 얻어 복제본 기반 프로파일링 대비 최대 감소폭이 각각 1.28, 1.54퍼센트포인트에 불과하다.

**은밀성(Stealthiness).** spy 프로세스를 켰을 때 추론 지연은 prefill 단계(L2 캐시 기반 Invalidate+Compare)에서 1~3%, decoding 단계(TLB 기반 Evict+Reload)에서 4~6% 증가하며 최악의 경우에도 8% 미만이다. 이는 스케줄링·자원 경합으로 이미 비슷한 변동이 발생하는 LLM 서빙 환경의 정상 지연 변동 범위 안에 들어, 추가 지연이 정상적인 시스템 잡음과 구별되지 않는다고 주장한다.

### 완화 기법 평가

직접적 완화책으로, 추론 중 중요도 점수로 선택된 토큰의 $A\%$를 입력과 무관하게 무작위 토큰으로 교체해 입력 의존적 희소성 패턴의 안정성을 교란한다. Financial QA에서 교란 강도 10%~30%로 평가한 결과, 강도가 커질수록 ASR은 일관되게 떨어지지만 생성 품질도 함께 저하된다. 기준선(Baseline)에서 LongChat-7B는 ASR 89.45%·ROUGE 0.43, LLaMA3-8B는 90.12%·0.48, Qwen3-8B는 91.23%·0.42였다. 10%에서는 각각 85.41%/0.38, 84.92%/0.35, 87.28%/0.37, 20%에서는 82.09%/0.32, 79.85%/0.24, 81.13%/0.35, 30%에서는 76.17%/0.21, 72.68%/0.16, 75.98%/0.26이 된다. 예컨대 30% 교란에서 LLaMA3-8B의 ROUGE는 0.48에서 0.16으로 떨어진다. 즉 희소 선택의 무작위화는 누출을 줄이지만 공격적인 교란은 생성 품질을 훼손한다.

그 밖의 방어로는 정밀 타이머·모니터링 인터페이스·메모리 관리 primitive 제한(트레이스 충실도를 낮추지만 비밀 의존적 접근 자체는 없애지 못함), 고정 혹은 page-padded 스케줄과 dummy KV 접근(희소 어텐션 효율을 희생), 테넌트 격리와 캐시/TLB 분할(런타임 또는 하드웨어 지원 필요), 반복적 probing이나 비정상 캐시/TLB 활동 탐지를 함께 쓰는 방안을 논의하며, 모형 품질과 서빙 효율을 모두 보존하는 저비용 방어는 향후 과제로 남긴다. 또한 현실적 시스템 잡음과 모형 변화 아래에서도 SpaRLeaK가 원래 공격 효과의 90% 이상을 유지한다고 보고한다.

## 고찰

### SIMA 부채널의 위치와 기존 공격과의 차이

이 논문이 제시하는 희소성 유발 메모리 접근(sparsity-induced memory access, SIMA) 부채널은 희소 어텐션(sparse attention)이 의미적 관련성에 따라 Key-Value(KV) 텐서를 동적으로 선택·적재하는 과정에서 발생한다. 이 접근은 LLM 서비스 인터페이스로 직접 노출되지 않지만, 공유 GPU 마이크로아키텍처 구성요소(캐시, TLB)에서 관측 가능한 경쟁(contention)을 유발한다. 저자들은 응답 시간이나 time-to-first-token 같은 timing 기반 공격[37, 50, 57, 63], 네트워크 트래픽 분석[28, 48], CPU 공유 캐시의 embedding table 접근 관측[1, 13]과 대비하여, SIMA는 모델에 내재적(model-intrinsic)이며 prefill과 decoding 두 단계 모두에 걸쳐 나타나므로 더 광범위하고 지속적인 프라이버시 누출을 가능하게 한다고 주장한다. 또한 Table 1의 비교에서 기존 공격들에는 예방·탐지 기법이 제시되어 있는 반면, SIMA에 대해서는 현재까지 효과적인 완화 수단이 보고되지 않았다는 점을 지적한다.

### 페이지 단위 관측이 만드는 정보 손실

가장 본질적인 제약은 공간적 조대함(spatial coarseness)이다. KV 텐서는 가상 메모리 페이지 단위로 관리되고[18], 한 토큰의 레이어별 KV는 통상 10–30 KB 수준이므로 하나의 페이지에 여러 토큰의 KV가 함께 배치된다. 따라서 공격자는 다수의 토큰 단위 접근이 하나의 사건으로 합쳐진 page-level SIMA trace만 관측하며, 토큰 단위 희소성 구조는 상당 부분 소실된다. 저자들은 정확한 복원을 시도하지 않고, 페이지 내 균등 분배가 희소 어텐션의 비균등 구조를 보존하지 못한다는 점을 근거로, 페이지별 누적 빈도를 토큰 단위 활성화 분포의 집중도를 지시하는 제어 신호로 사용하는 분포적 재구성을 택한다. 즉 고빈도 페이지는 더 치우친(long-tailed) 토큰 참여로, 저빈도 페이지는 더 평탄한 참여로 모델링된다. 이 선택은 근사적일 뿐이며, 실제 토큰 단위 패턴과의 일치를 보장하지 않는다. 재구성의 필요성은 ablation에서 확인되는데, 페이지 크기 20 토큰에서 재구성을 적용하지 않으면 Healthcare PASR이 57.45%까지 떨어진다.

### 위협 모형에 내재된 가정

공격 성립 조건은 적지 않다. 피해자 애플리케이션이 요청 간에 공개된 고정 system-prompt 템플릿을 재사용하고, 모델과 런타임 구성이 고정되어 있어야 하며, 공격자는 동일 물리 GPU에 상주하는 비특권 spy 프로세스를 실행할 수 있어야 한다. 공격자는 GPU 스케줄링이나 정확한 실행 타이밍을 제어할 수 없고, 피해자 메모리나 정확한 실행 시점 주소를 획득하지도 못한다. 대신 해당 prompt-side KV 페이지에 대한 경쟁 기반 probe 매핑을 오프라인에서 보정해 두고 여러 호출에 재사용한다는 가정에 의존한다. 이 가정은 장수(long-lived) 모델 프로세스를 유지하는 서빙 환경[62]에서 prompt-side KV 할당이 요청 간 재사용된다는 관찰로 정당화된다. 단계 구분에 사용한 Nsight Systems[32] 기반 커널 타임라인은 저자들의 환경에서 root 권한 없이 접근 가능했다는 조건부 사실로 제시되며, 동일한 전이는 수집된 L2/TLB trace의 강도와 주기성에서도 직접 추론할 수 있다고 보완한다. decoding 단계에서는 probing window 길이 $\Delta$가 스케줄링 지터로 인해 한 decoding step과 정확히 정렬되지 않을 수 있어, 인접 window의 측정을 집계하고 다수결(majority voting)로 과도 노이즈를 억제한다.

### 공격 설계상의 선택이 남기는 의문

Autoregressive Token Recovery(ATR)는 전체 어휘 분류의 복잡성과 클래스 불균형을 줄이기 위해 오프라인 프로파일링 코퍼스에서 구성한 과제별 후보 집합(restricted token prediction space)을 온라인 실행 전에 고정해 재사용한다. 저자들은 성능 향상이 SIMA에서 오는지 후보 집합 제한에서 오는지를 보충 실험에서 검토한다고 밝히며, 이 구분이 결과 해석에 중요함을 스스로 인정하는 셈이다. 또한 오프라인 비용은 무시할 수 없다. 프로파일링에는 모델당 QAI 5,000 질의와 ATR 응답 3,000/3,000/2,000개(LongChat-7B, LLaMA3-8B, Qwen3-8B)가 사용되며, ATR은 decoding 전 구간의 step-wise 패턴을 기록하므로 응답 길이에 비례해 12.7~19.5시간이 소요된다. 다만 이는 동일 구성에서 재사용되는 일회성 비용이다. 모델 가중치나 희소 어텐션 구성을 알 수 없는 경우에는 target-interactive profiling으로 전환하여, 평균 PASR 90.97%, DASR 86.65%를 얻고 복제본 기반 프로파일링 대비 최대 1.28/1.54 퍼센트포인트만 감소한다고 보고한다.

### 은밀성과 완화 방안의 상충

공격의 실용성은 피해자 실행을 눈에 띄게 교란하지 않는지에 달려 있다. 측정 결과 spy 프로세스는 prefill 단계에서 1–3%, decoding 단계에서 4–6%의 추론 지연 증가를 유발하고 최악의 경우에도 8% 미만이어서, 스케줄링과 자원 경쟁으로 이미 유사한 변동이 존재하는 LLM 서빙 환경의 정상 지연 변동 범위 안에 든다고 해석한다. 완화 측면에서 저자들이 직접 평가한 방법은 입력 비의존적 무작위성 주입으로, 중요도 점수로 선택된 토큰 중 $A\%$를 입력과 무관하게 다른 토큰으로 교체한다. Financial QA에서 10~30% 강도로 실험한 결과 ASR(PASR과 DASR의 평균)은 일관되게 감소하지만 생성 품질도 함께 저하되는데, 30% 강도에서 LLaMA3-8B의 ROUGE가 0.48에서 0.16으로 떨어진다. 그 외에 세밀한 타이머·모니터링 인터페이스·메모리 관리 프리미티브 제한은 trace 충실도를 낮추지만 비밀 의존적 접근 자체를 제거하지 못하고, 고정 또는 페이지 패딩 스케줄과 더미 KV 접근은 희소 어텐션의 효율을 대가로 입력 의존성을 줄이며, 테넌트 격리와 캐시/TLB 분할은 교차 테넌트 관측을 막지만 런타임 또는 하드웨어 지원이 필요하다. 반복적 probing이나 비정상 캐시/TLB 활동 탐지는 보조 수단이 될 수 있다. 저자들은 모델 품질과 서빙 효율을 함께 보존하는 저비용 방어를 향후 과제로 남긴다.

## 결론

SpaRLeaK는 희소 어텐션 기반 LLM 서빙에서 마이크로아키텍처 프라이버시 누출을 다룬 첫 연구로, 희소 어텐션이 비밀 의존적 KV 접근을 통해 공유 GPU 자원에 SIMA 패턴을 남긴다는 점을 규명했다. prefill 단계에서는 L2 캐시 기반 Invalidate+CompaRe로 누적 SIMA trace를, decoding 단계에서는 TLB 기반 Evict+Reload로 단계별 SIMA trace를 추출하고, page-level 관측에서 근사적 토큰 단위 희소성 프로파일을 재구성한 뒤 프로파일링 기반 학습을 적용해 Query Attribute Inference(QAI)와 Autoregressive Token Recovery(ATR)를 end-to-end로 실현했다. 세 가지 LLM 아키텍처, 세 가지 희소 어텐션 메커니즘, 세 가지 프라이버시 민감 데이터셋에 걸친 평가에서 평균 공격 성공률은 속성 추론 90.9%, 응답 복원 87.3%였고, 현실적인 시스템 노이즈와 모델 변화 아래에서도 원래 공격 효과의 90% 이상을 유지했다. 이는 희소 어텐션 기반 LLM 시스템을 배치할 때 SIMA 누출을 반드시 고려해야 함을 시사하며, 저자들은 익명화된 SIMA trace, 학습된 공격 모델, 평가 스크립트, 문서를 아티팩트로 공개한다.
